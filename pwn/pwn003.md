# PWN#003 — Notes Vault — pwn — 45 pts

**Cible :** `169.58.126.107:5002` · **ID :** 20 · **Statut :** accepté par la plateforme
**Flag :** `CTF{REDACTED}`

## Énoncé

> Get a shell on the remote host and read the flag.

Le service fournit une Notes Vault interactive : Add, Free, Edit, View. Le binaire fourni est un ELF x86-64 PIE. Le menu expose un pointeur de fonction de formatage par note.

## Fuite PIE et allocator

Au démarrage, le service affiche une adresse de `main` dans son message de debug. Avec `main` à l'offset `0x1af8`, la base PIE est `main_leak - 0x1af8`.

Les contenus de taille 32 sont servis par un allocator de pool avec freelist. La fonction `mangle(ptr, node)` encode le pointeur suivant comme `ptr XOR rol(node, 13)`. Après avoir créé puis libéré la note 0, `view(0)` reste possible et affiche les octets du chunk libéré : c'est le use-after-free. Comme le chunk était seul dans la freelist, le pointeur encodé se décode par `ror(encoded, 13)` et révèle l'adresse du chunk.

## Empoisonnement de freelist et fuite libc

L'édition de la note libérée remplace le premier mot du chunk par un pointeur encodé vers `notes_storage + 24`, qui est le début des métadonnées de la note 1 :

```text
encoded_next = target XOR rol(chunk, 13)
target       = PIE_base + 0x40e0 + 24
```

Les deux allocations suivantes renvoient d'abord le chunk original, puis la cible empoisonnée. La deuxième allocation permet ainsi d'écrire dans les métadonnées de la note 1 : son formateur devient `puts@plt`, son contenu pointe vers `puts@GOT`. `view(1)` appelle alors `puts` sur l'entrée GOT et divulgue l'adresse résolue de `puts`.

La base libc est calculée par `puts_leak - 0x82060` ; l'alignement page a été vérifié sur le service distant. L'offset `0x82060` correspond à `puts` dans la libc fournie avec PWN#002, et `system` se trouve à `libc_base + 0x54790`.

## Appel de `system` et lecture du flag

Le même alias des métadonnées permet de remplacer le formateur de la note 1 par `system` et son argument par l'adresse du chunk contrôlé. Le contenu du chunk est préparé avec une commande de lecture du fichier de flag. `view(1)` déclenche alors `system(chunk)` ; le flag a été observé dans la sortie distante puis soumis manuellement et accepté par la plateforme.

## Chaîne résumée

1. Lire la fuite debug pour calculer la base PIE.
2. Ajouter la note 0 (taille 32), la libérer, puis la relire pour observer le pointeur freelist encodé.
3. Éditer le chunk libéré afin d'empoisonner la freelist vers les métadonnées de la note 1.
4. Réallouer deux chunks pour détourner le callback de formatage et divulguer `puts@GOT`.
5. Calculer la base libc, placer la commande dans le chunk contrôlé, remplacer le callback par `system`, puis afficher la note pour lire le flag.

## Analogie vie réelle

Imagine un atelier avec un casier partagé : une fiche de rangement indique où se trouve un dossier et quelle personne doit le traiter. Après qu'un dossier est déclaré détruit, l'atelier le laisse pourtant consultable. En modifiant sa fiche, on peut rediriger le prochain rangement vers la fiche d'un autre dossier, puis remplacer le nom du préposé par celui d'une personne qui exécute les instructions écrites dans le dossier.

| Monde réel | Technique |
|---|---|
| Adresse affichée sur le tableau de l'atelier | Fuite de l'adresse de `main`, qui révèle la base PIE |
| Dossier consultable après sa destruction | Use-after-free de la note |
| Fiche de rangement qui dirige le prochain dossier | Pointeur encodé de freelist et empoisonnement |
| Fiche d'un autre dossier | Métadonnées de formatage de la note 1 |
| Préposé chargé de traiter le dossier | Callback `puts`, remplacé par `system` |
| Adresse du bureau central divulguée par le callback | Fuite `puts@GOT`, puis calcul de la base libc |
| Instructions écrites dans le dossier | Commande de lecture du flag dans le chunk contrôlé |

## Cause

Le service combine trois défauts : une note reste consultable et modifiable après `Free`, le pointeur de freelist est forgeable après fuite de l'adresse du chunk, et la fonction de formatage conservée dans les métadonnées est appelée sans validation. L'ASLR est contourné par les fuites debug et GOT.
